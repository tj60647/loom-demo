## New since 7 August — the guide thread's own punch-list items

**N1 · The unlabeled toast points at a panel that will not show the passage.**
*The highest-severity item on this list.* [PdfViewer.tsx:2120](../src/components/pdf/PdfViewer.tsx#L2120)
says *"Passage captured — **unlabeled**. Name it in Your work whenever the word
arrives."* Your Work is built entirely from concepts —
[OpenTab.tsx:560-565](../src/components/tabs/OpenTab.tsx#L560) derives `here`
and `namedOnly` from `scoped.concepts`, and each row lists
`scoped.passages.filter(b => b.conceptIds.includes(concept.id))` — so a
conceptless passage matches no group. The toast's "In your work ›" button
resolves `targetPassage.conceptIds[0]` to `undefined` and **opens the sheet onto
nothing.** Meanwhile the tally goes +1, because `scoped.passages` filters on
`sourceId` alone. *The count says one more, the list shows nothing, and the
toast names the list.* Same defect shape as items 2 and 3, freshly made.

**N2 · With Your Work already open, an unlabeled capture is silent.**
[PdfViewer.tsx:677-684](../src/components/pdf/PdfViewer.tsx#L677) suppresses the
toast when the sheet is out, on the stated reasoning that *"the row IS the
acknowledgement"*. For an unlabeled passage there is no row. No toast, no row,
no acknowledgement — only the count ticking.

**N3 · A side effect of N1.** `Workbench.tsx` keeps `map` mounted once visited
and `OpenTab.tsx:271` queries `document` globally, so `[data-passage-id]` can
match MapTab's `#unfiledPassages` row and scroll an off-screen tab.

**N4 · The two copies of the naming coaching now contradict each other.**
[CaptureModal.tsx:204](../src/components/pdf/CaptureModal.tsx#L204) promises
*"Or leave it empty: the passage is kept either way."*
[OpenTab.tsx:470-472](../src/components/tabs/OpenTab.tsx#L470) does not — and
that form still refuses an empty concept. The app now tells a student two
different things about the same act depending which capture path they used.
This turns item 8 from a tidiness fix into a correctness one.

**N5 · `workflows.ts` now describes a guide that no longer exists.** Its label
reads *"Try the moves first — **nothing is kept**"*, the exact sentence TJ
ordered removed on 2026-08-12 (*"i dont expect tutorial to keep my work"*) and
which `tests/practice-guide.spec.ts` now forbids on screen. It also calls the
place "practice loom" where the app has said **the guide** since `66c5950`, and
it draws only `library → practice` while the guide is reachable from every page
for any signed-in user. AGENTS.md makes this a same-commit obligation, and
`scripts/check-workflows.ts` cannot catch any of it — nothing in it reads the app.

**N8 · Two real `tallyByReading` defects.** [scope.ts:161-162](../src/lib/scope.ts#L161)
claims *"the same rule the workbench uses, so the card and the tab agree."* It is
false twice. **(a)** The tally's concept set is rule B (a passage from this
reading) while the workbench uses rule A (which also admits concepts with no
passage anywhere), so a thread between two un-evidenced concepts — legal, and
listed as that reading's thread on 02 — **is counted by no library card on any
reading, ever**, until an end gains a passage. **(b)** Even aligned, the card's
thread number is `scoped.edges + scoped.bridges`, the *sum* of two numbers shown
separately on 02 and in the reading header. It matches neither, by construction.

**N9 · A count surface that lies in words.** [ThrowTab.tsx:445-448](../src/components/tabs/ThrowTab.tsx#L445)
says *"The concepts **this reading** evidences — the ones you captured a passage
for here"* while rule A deliberately also admits every concept with no passage
anywhere — contradicting the "no evidence" tag six lines below it. Folds into 2.1.

**N10 · The hash gate is load-bearing and completely unasserted.** No test
references `pageContentHash`, `offsetsTrusted` or `liveHash`; the highlight specs
only assert that a `.loom-passage-highlight` exists, **which the fuzzy fallback
also produces**. A total hash break is green in CI and silent in the UI. This is
pre-existing, but item 13 now depends on it — see 3.1.

*(N6 and N7 are doc defects: `contracts.md` closes the Unlabeled-Passage
invariant while still calling the graph-view group "P1.9" when that group already
exists on 03; and the wheel/mask fix in `66ad390` is filed as TJ's with no TJ
words behind it anywhere in the diff. Both belong in Wave 0′.)*

## Wave 4′ — the reading surface

**4.1 · Item 14, both halves.** **14b first** — it is one line of intent and is
most of what JC actually saw. The viewer unmounts on tab change and `setPdfPage`
has a single caller, so the page is simply never committed at teardown. **14a**
changed shape: the first draft said "the data exists at ingest", but
`probePdfStructure`'s per-page `kind` is computed and **discarded** — only
aggregate counts persist. The cheaper route it missed: `sourcePages.textContent`
is already stored per page, so `firstTextPage = min(pageNumber) where
length(textContent) > floor` is derivable from rows already in hand, with no
re-probe and no new ingest step.

**4.2 · Item 12.** Five bars confirmed unchanged — up to **eight** for staff with
search open. **Two of the first draft's claims here were wrong:** there is no
⌘F-style binding (the viewer binds bare `f` to fullscreen and explicitly excludes
the modifiers so the browser's own find still works), and the two boxes do **not**
search the same text. ShelfSearch also searches the student's own work; the
viewer's is the only one that moves the page and paints the matched words. So the
decision is not "which survives" but "which capability moves where" — see
decision 5.

**4.3 · Item 13 — last, and sized alone.** Diagnosis confirmed verbatim at HEAD.
Add to the first draft's scope: there are **four** render paths, not three; the
rect layer must mount **outside** `.react-pdf__Page__textContent`; and **N10's
missing hash assertion lands first.** The reason is the whole risk of this item —
the layer would otherwise mount inside the element whose `textContent` is hashed
at capture and again at mark time, and one text node there shifts every stored
offset for every student, retroactively and silently. Two weeks before a cohort
is the worst possible time for that.

## The guide tripwire

New since the first draft, and it constrains most of this list. `npm run check`
runs `check:guide`, which asserts by **literal string match** — so converting
`id="captureConcept"` to `id={...}` turns the build red, and *moving* a control
can pass the check while the guide silently points at nothing.

**Ids this list touches, that the guide rings:** `#captureConcept` (item 9),
`#capturePassageNote` (7), `#capturePassageSave` (4), `#warp` (6, 18),
`#triageList` (5, 6), `.pdf-stage` and `#captureNow` (13), `#mapKit` (15).

**Live DOM predicates, unguarded and silent when broken:** the thread beat reads
`#throwBench .sleeper:not(.asleep)` and the **first** `#throwBench textarea` —
add a textarea above it and guide move 2 never completes. The mask's wheel
pass-through reads `document.querySelector("main")` and its scroll chain, which
item 12's auto-hide would change.

**Copy strings pinned by the specs:** `"Save unlabeled"` on a blank field (which
**locks the decision the first draft filed as open** — see decision 2), the toast
matching `/unlabeled/i`, and `#yourwork-toggle` matching `/·\s*(\d+)/` and being
byte-identical across a round trip.

**CSS is parsed out of `globals.css` by regex** (`NAME\{[^}]*\}`), so splitting a
rule across two selectors breaks the parse. Items 12 and 13 both edit that file.

**Rule:** anyone touching `CaptureModal.tsx`, `ThrowTab.tsx`, `MapTab.tsx`,
`PdfViewer.tsx`'s `#yourwork-toggle`, or `globals.css` runs `npm run check` **and**
`tests/practice-guide.spec.ts` — not just the type-check.

## Decisions

1. **What P1.9 now means** (0.4). *Default:* close it, and file "unlabeled
   passages as nodes on the board" as a new named item if it is wanted.
2. **"Save unlabeled" vs "Save Passage."** The first draft filed this as open and

   tested, legible — but **record it as a ruling** so it stops being an
   unattributed agent choice.
3. **`passage.question` — wire it or retire it.** TJ's words say "notes or
   gloss", silent on question. *Default:* retire it explicitly in `contracts.md`,
   or scope it into 1.2. Leaving it half-built is the state that produced item 7.
4. **21 vs 20 on 01 Reading.** *Default:* the header names the split — *"20
   evidenced here · 1 named, no evidence yet"* — since deleting the distinction
   contradicts a ratified rule and 02 already shows "no evidence" per concept.
5. **Which search capability moves where** (4.2, re-framed). *Default:* keep both
   capabilities and one control — fold "jump to the page and paint the words"
   into the persistent field when a `sourceId` is present, and delete the toolbar
   button. One bar less, no capability lost.
6. **Item 18's tab reorder.** *Default:* cheap variant only.
7. **Item 19.** If it is Vercel's, say so to JC in the same message that closes
   the item — he will keep seeing it.
