# Loom — Full audit and alpha assessment, 2026-08-02

A complete pass over both journeys (learner and admin), the auth/data surfaces behind
them, and the test estate — against master `9abbdd7`. Written to answer one question:
**is this ready for alpha testers, and what has to be true before production?**

Companions: [contracts.md](contracts.md) (every contract surface, exhaustively),
[loom-spec-v1.md](loom-spec-v1.md) (the build contract),
[v14-parity-audit.md](v14-parity-audit.md) / [v14-ui-language-diff.md](v14-ui-language-diff.md)
(feature parity and copy, last reconciled 7/31–8/1).

## Verdict

**Ready for alpha, with three conditions.** The learner journey is complete,
coherent, and honest to the spec: every station works, the red lines hold, data is
exportable at every step, and the mirror/scope/import invariants are genuinely
enforced in code (see contracts §5). The admin surface covers the full course
lifecycle. Nothing found in this audit is a red-line violation.

The three conditions, in order:

1. **The first-OAuth enrolment path must be smoke-tested manually** before testers
   arrive. It was rewritten 8/1 (`events.signIn`), Playwright structurally cannot
   reach it (the backdoor bypasses OAuth), and if it is wrong every tester is locked
   out at the door. One fresh GitHub account, invited, signing in, landing on
   Readings — that is the whole test.
2. **The suite must be green end-to-end** before it can gate anything.
   As of the 8/1 hand-off it fails order-dependently in `maps.spec.ts`
   (8 passed / 1 failed / 3 skipped by serial mode — the "3 did not run" were the
   remaining maps tests, not pdf-viewer). Status and fix: see §5 and the session
   report accompanying this audit.
3. **Production must be built with the dev-only bypasses verified off.** They are
   all correctly gated on `NODE_ENV === 'production'` today (S-1..S-3 below), which
   is fine *as long as nothing ever deploys with NODE_ENV unset*. The deployment
   docs pin this.

Severity scale: **Blocker** (fix before alpha testers) · **High** (fix before
production / first graded use) · **Medium** (fix during alpha) · **Low** (recorded,
schedule freely) · **Closed** (fixed since the 8/1 hand-off).

## 1. The learner journey, station by station

Route → station map, all rendered under one journey bar
([JourneyNav.tsx](../src/components/ui/JourneyNav.tsx)): a station you can work at
*here* is a button (workbench tab); every other station is a link.

| Station | Where | State |
| --- | --- | --- |
| 00 Readings | `/` (shelf by week, own tallies, untethered-passage placement, "a reading of your own", worked example for empty looms) | **Solid** |
| 00 Reading | `/reading/[id]` tab `reading` — PDF with page/strip/matrix layouts, fit modes, spread, fullscreen; select → Capture as Byte; prior bytes highlighted (precise when hashes match, fuzzy otherwise); highlight → coding log jump | **Solid**, newest features untested (T-5) |
| 01 Open | tab `open` (inside a reading only) — capture form with word chips + coaching ladder, coding log with rename/edit/refile/delete, cross-reading reuse notes | **Solid** |
| 02 Throw | tab `throw` / `/weave?tab=throw` — warp list, other-readings band, shuttle (incl. across readings), openers, coin-a-term with tongues, bridges band, undo/redo | **Solid**, zero test coverage (T-2) |
| 03 Read | tab `read` / `/weave?tab=read` — arc cloth, counted prompts (spine/centre/gap/words), walking-order reading pane, essence + paragraph per map, map kit, history panel (whole weave) | **Solid**, zero test coverage (T-2); one wrong-rail bug (U-6) |
| 04 Map | tab `map` / `/weave?tab=map` — sort list with drag/arrows, tier chips, plural maps per scope with switcher/rename/export/delete, card table with bands/bends/pins, counted mirror | **Solid** |
| 05 Weave | `/weave` — throw/read/map as tools of one station, underline stays on Weave | **Solid** |
| 06 Keep | `/keep` — per-map .json/.md, whole-cloth .json/.md, import (additive map / destructive cloth, correctly routed and confirmed), reset that spares history | **Solid**, two loading-window bugs (U-1, U-2) |

Scope is read off the route and derived per render from `byte.sourceId`
([scope.ts](../src/lib/scope.ts)); concepts are never owned or re-homed; bridges
are first-class. This all matches the spec, including the deliberate oddity that a
byte-less concept appears in every scope (red line #4's visible failure state).

## 2. The admin journey

One structural gate — [admin/layout.tsx](../src/app/admin/layout.tsx) redirects
non-admins to `/`. Five surfaces: Roster (`/admin`), Cohort Map (`/admin/aggregate`),
per-student loom (`/admin/user/[id]`), Readings (`/admin/library`), Courses
(`/admin/courses`). Full capability inventory in contracts §2b–2d.

The course lifecycle is complete: create course → sections → upload readings
(browser→Blob, 20 MB cap enforced in three mutually-distrusting places, extraction
scoring with abstention semantics, optional metadata drafting that proposes and
never stores) → schedule by week → publish/hide → bulk-invite roster (with section
placement) → watch the cohort → soft-remove (work survives, re-invitation
reinstates). Invitation, enrolment, and access are correctly three separate things.

What's thin, deliberately or not:

- **Authorization is one global flag.** Any admin administers every course; there
  is no per-course instructor scoping anywhere (`courseMemberships.role` exists
  but is never read). Fine for one course in Fall 2026; a decision to make before
  a second instructor exists.
- The guard is a property of the **call graph, not the route**: four of five admin
  pages have no in-page check and rely on the layout plus whichever action they
  call. Sound today; fragile under refactoring (S-6, S-10).
- The legacy site-wide allowlist admits people **no admin surface can see or
  revoke** (S-7).

## 3. Security findings

### Dev-only bypasses — correctly gated today, worth an env audit at every deploy

- **S-1 (High, pinned).** `getUserId()` impersonates `tjm@tjmcleish.com` — the
  admin — whenever there is no session and `NODE_ENV !== 'production'`
  ([loom.ts:19](../src/actions/loom.ts#L19)). Every one of the 21 loom actions
  roots here: in any non-production deployment, an unauthenticated caller reads
  and writes the admin's graph.
- **S-2 (High, pinned).** `/api/readings/[sourceId]` requires a session only in
  production ([route.ts:43](../src/app/api/readings/%5BsourceId%5D/route.ts#L43));
  `authorizeSourceFile` skips the same way
  ([sources.ts:679](../src/actions/sources.ts#L679)). The cover route has no check
  of its own and inherits this.
- **S-3 (Medium).** `/api/auth/test-login` is production-403'd as its first
  statement — but that is its *only* guard (no secret, no allowlist). It mints an
  ADMIN user row and echoes the session token in the response body. Any deployment
  where `NODE_ENV` isn't exactly `production` exposes a one-click admin session.

These three share one property: they are safe **iff** `NODE_ENV === 'production'`
in every deployed environment. Vercel sets this for production and preview builds,
so the practical risk is a self-hosted or misconfigured environment. Deployment
docs now state this as an invariant to check.

### Real gaps, environment-independent

- **S-4 (High).** Hardcoded admin fallback emails
  ([auth.ts:9](../src/lib/auth.ts#L9)) bypass `users.role` entirely — control of
  either GitHub account = full admin, invisible to the DB, not env-configurable.
  Should become an env var (`LOOM_ADMIN_EMAILS`) before any non-TJ deployment.
- **S-5 (Medium).** `createSource` writes the uploaded blob **before** its
  admin check runs ([sources.ts:297-336](../src/actions/sources.ts#L297-L336)),
  outside the `readings/` prefix, with no cleanup on the failure path. It has no
  callers — dead code that is still a POSTable server action. Delete it, or move
  `requireAdmin()` to the first line.
- **S-6 (Medium).** `/admin/aggregate` wraps its only action call in
  `try/catch`, which swallows `checkAdmin()`'s `NEXT_REDIRECT`
  ([aggregate/page.tsx:38-47](../src/app/admin/aggregate/page.tsx#L38-L47)) — the
  action-level guard is inert there; only the layout protects the page.
- **S-7 (Medium).** The legacy `allowed_email` table grants permanent app access,
  has **no admin UI**, and `removeFromRoster`'s session revocation never fires for
  anyone on it. Either build the surface or migrate the rows to invitations and
  drop the table.
- **S-8 (Medium).** An invitation to *any* course grants app-wide sign-in, and
  invitations never expire. Acceptable for alpha; revisit before multi-course use.
- **S-9 (Low).** `deleteCourse`'s typed-"delete" confirm is client-supplied — a
  direct POST satisfies it trivially, and despite its comment it performs no
  student-work check (cascades are soft, so work survives via `courseId → NULL`).
- **S-10 (Low).** No middleware; three guard implementations with three failure
  modes (redirect / throw / throw-with-re-read). Consolidating into one
  `requireAdmin` would make the admin surface auditable at a glance.
- **S-11 (Low).** `inviteLearners` accepts an unbounded paste (no cap, no rate
  limit).
- **S-12 (Low).** Import actions trust client-side parsing for shape; the server
  re-validates sizes, source existence, and ownership only. Bounded by
  `IMPORT_LIMITS`, and rows are user-scoped — worth a server-side shape check
  eventually, not urgent.
- **Closed.** pdf.js worker no longer loads from unpkg — vendored into `public/`
  at build (`0f9f01b`, [copy-pdf-worker.mjs](../scripts/copy-pdf-worker.mjs)).

## 4. Product / UX findings (learner)

- **U-1 (Blocker, small fix).** `/keep` gates only on auth status, not on
  `useLoom().isLoading` — during the load window it shows "no maps yet",
  offers **Export .json, which downloads an empty file**, and the reset confirm
  reads "0 concepts … all go"
  ([KeepPage.tsx:13](../src/components/shelf/KeepPage.tsx#L13),
  [KeepTab.tsx:27-30](../src/components/tabs/KeepTab.tsx#L27-L30)). A tester who
  exports during load holds a file that looks like their artifact and is empty —
  red line #5 adjacent. Gate the page (or its buttons) on loading.
- **U-2 (High).** Silent failure on the core gestures: `handleAddByte`,
  `handleThrow`, `setTier`, `makeAllPrimary`, essence/paragraph writes — all
  unhandled promise rejections. A failed capture does *nothing visible*; the
  60-map cap error is thrown where nothing catches it
  (inventory with line numbers in the session log; e.g.
  [OpenTab.tsx:53](../src/components/tabs/OpenTab.tsx#L53),
  [ThrowTab.tsx:166](../src/components/tabs/ThrowTab.tsx#L166)). One
  `.catch(resync)` per gesture path fixes the class.
- **U-3 (High).** Two save-loss mechanisms around map text, both confirmed or
  reproduced on 8/2:
  (a) *first-keystroke race* in a fresh scope — essence/paragraph keystrokes
  queue under the temp map id and the real id simultaneously; the stale
  one-character write can flush last. Confirmed variant while building the
  suite: a **rename typed during the create round-trip persists server-side
  but never reaches the UI** (the optimistic update targets the real id while
  the local row still carries the temp id) — on a warm server this hits every
  time;
  (b) *navigation aborts in-flight saves* — the debounced essence/paragraph
  flush is a plain action POST, and navigating (or reloading) kills it
  mid-flight (`Error: aborted / ECONNRESET` server-side), losing the write
  with no retry and no message. (b) was the actual root of the suite's
  order-dependent failure (see T-1). A `keepalive` fetch or retry-on-mount
  would close (b); the id-alias flush ordering closes (a).
- **U-4 (Medium).** During "Loading your loom…", the journey bar renders with no
  `onStation` handlers — every station is a link, so clicking "04 Map" inside a
  reading navigates to `/weave?tab=map` instead of switching tabs.
- **U-5 (Medium).** ThrowTab's window-level Ctrl+Z listener stays live from the
  keep-alive hidden tab — undo on Read/Map silently reverts a coined term on a
  thread the student can't see.
- **U-6 (Medium).** Read's rail step "write" reads the mirror (`state.read`),
  not the active map — inside a reading, writing a full paragraph never lights
  the step ([ReadTab.tsx:120](../src/components/tabs/ReadTab.tsx#L120)).
- **U-7 (Medium).** PDF failure shows developer voice ("Failed to load PDF.
  Check file path.") with no retry, for every cause from 401 to offline.
- **U-8 (Low).** Leaving station 00 unmounts the viewer; reading position, zoom,
  and layout reset on return.
- **U-9 (Low).** `goto` is enabled-but-dead on reference-only readings.
- **U-10 (Low).** Signed-out surfaces drop all navigation (no journey bar, no
  link home; the wordmark isn't a link).
- **U-11 (Low).** Accessibility debt: `span onClick` controls (about, coin,
  remove, tier chips, log-row headers), hover-only tooltips, and the mobile
  journey bar squeezing link-stations instead of scrolling.
- **U-12 (Low).** `/weave?tab=` is initial-state only — back/forward changes the
  URL without changing the tab; unknown values silently become `throw`.
- **U-13 (Low).** An unenrolled learner sees "no readings published to your
  course yet" — indistinguishable from "you were never enrolled", with no path
  to resolve from inside the app.

## 5. Test estate

12 tests / 6 files, one worker, one shared account (Test User A via the
`test-login` backdoor), storage states minted in global-setup with the walkthrough
pre-dismissed. Full inventory in the session log.

- **T-1 (Blocker for gating — root-caused and fixed 8/2).** The suite was not
  green end-to-end: `maps.spec.ts:42` failed order-dependently ("essence still
  empty after reload"). Root cause, reproduced live: the spec waited on
  `#saveDot`, but any save's 1500 ms flash satisfies that wait — on a **warm**
  server (i.e., mid-suite) the tier save's flash was still showing, the wait
  passed instantly, and the reload **aborted the essence POST in flight**
  (`ECONNRESET` in the server log). Cold solo runs were slow enough to sync by
  accident. Fixed by waiting on the specific action POST (matched by body) and
  sweeping stranded temp maps at spec start; serial-skip had also been
  skipping cleanup, stranding a `PW temp map` each failed run. The learner
  bug underneath is U-3(b).
- **T-2 (High).** Stations 02 Throw and 03 Read have zero coverage — edges
  (the product's core claim), coined terms, essence/paragraph, history. Admin has
  render-assertions on one screen of one tab; **no admin action is ever
  executed**. Keep covers export-json only: import, reset, worked example,
  geometry saves all uncovered. Addressed by the new journey specs.
- **T-3 (Medium).** `audit-seed.spec.ts` and `audit-seed2.spec.ts` (2 of 12)
  contain **no assertions** — green regardless of outcome. Delete or promote.
- **T-4 (structural).** The real OAuth path — sign-in gate, `events.signIn`
  enrolment — is unreachable by the backdoor-based suite. Manual smoke test
  before every auth-touching release (memory note exists; condition 1 above).
- **T-5 (Medium).** The newest master features (strip/matrix layouts, 8× zoom,
  zoom-aware re-render) have no tests.
- **T-6 (Low).** Five hard `waitForTimeout` sleeps; `ui-audit.ts` and root
  `audit.ts`/`audit2.ts` are broken/stray tooling to retire.

## 6. Contract / data findings

- **D-1 (tracked).** The mirror dual-write (`concept.tier`, `reads`, cardTable
  echo) awaits its contract migration — NEXT_SESSION item 4. Two accepted quirks
  documented there. The `map` table is authoritative either way.
- **D-2 (Medium).** `saveRead` is deprecated, uncalled — and still an exported
  server action, the one writer that can desync the mirror. Remove the export.
- **D-3 (Medium).** Invariants enforced only in code, not schema: one label =
  one concept (checked in `updateConcept`, **not** `createConcept` — a race or a
  direct call can create case-duplicates), no unique on `user.email`, none on
  `source_page(sourceId, pageNumber)`. Candidates for the same migration as D-1.
- **D-4 (Low).** `scripts/apply-db-compat.ts` is an ad-hoc patcher behind the
  real migrations — retire it. `scripts/run-migrations.ts` duplicates
  `drizzle-kit migrate` — keep one.
- **D-5 (noted).** `deleteConcept`'s edge guard and `refileByte`'s dedupe filter
  on `userId` only (not course) — harmless single-course, worth knowing.
